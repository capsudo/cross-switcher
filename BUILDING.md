# Building Cross Switcher

Cross Switcher is a GNOME Shell extension. During development, use this checkout
directly through a symlink in GNOME Shell local extensions directory.

Extension UUID:

```text
cross-switcher@capsudo.github.com
```

## Required Tools

Needed for normal development:

```text
make
glib-compile-schemas
gdbus # optional unless using one-shot commands; waits for nested shell without sleep
gnome-extensions
gnome-shell
dbus-run-session
zip # optional, only needed for `make zip` / `make install`
unzip # optional, only needed for `make zip` / `make install`
```

## TLDR; One-Shot Instructions

### 1. Build and Link Extension

This will:
- build
- create symlink
- verify symlink points to this checkout

```sh
set -euo pipefail

extension_uuid="cross-switcher@capsudo.github.com"
extension_link="$HOME/.local/share/gnome-shell/extensions/$extension_uuid"

make all

mkdir -p ~/.local/share/gnome-shell/extensions
ln -sfnT "$PWD" "$extension_link"
ls -ld "$extension_link"

test "$(readlink "$extension_link")" = "$PWD"
```

### 2. Start Nested Shell and Enable Extension

This will:
- start/restart nested DBus session for shell and helper commands
- wait for GNOME Shell D-Bus service, no fixed sleep
- wait until Cross Switcher is visible to GNOME Shell
- enable extension in this session

```sh
dbus-run-session -- bash -lc '
  set -euo pipefail
  extension_uuid="cross-switcher@capsudo.github.com"

  (
    if ! gdbus wait --session --timeout 30 org.gnome.Shell; then
      echo "GNOME Shell did not appear on nested DBus session" >&2
      exit 1
    fi

    for _ in {1..60}; do
      if gnome-extensions info "$extension_uuid" >/dev/null 2>&1; then
        gnome-extensions enable "$extension_uuid"
        echo "Enabled $extension_uuid"
        exit 0
      fi

      sleep 1
    done

    if ! gnome-extensions info "$extension_uuid"; then
      echo "Extension $extension_uuid is not visible to nested GNOME Shell" >&2
      exit 1
    fi
  ) &

  exec gnome-shell --devkit --wayland
'
```

Notes:

- _A closed DBus session (`dbus-run-session`) cannot be reused; when nested shell exits, its DBus session is gone too._

- _Enabled extension state is stored in GNOME settings, so after enabling once it should usually stay enabled for next nested shell start. The command below still runs `gnome-extensions enable`, because it is safe to repeat and makes restart flow explicit._

- _`gdbus wait` avoids fixed sleep after starting shell. It returns when `org.gnome.Shell` appears on the nested session bus. `gnome-extensions info` then verifies the extension is visible before enabling it._

- _GNOME Shell runs as main foreground process. Helper commands run in background inside same DBus session. If helper command fails, nested shell keeps running so DBus session is not closed while GNOME Shell is still starting._

- _`org.gnome.Shell` can appear before GNOME Shell finishes scanning extensions. The loop waits (up to 1 min) until this specific extension is visible before enabling it._

## Detailed Instructions

### Build

Compile GSettings schema:

```sh
make all
```

This generates:

```text
schemas/gschemas.compiled
```

`schemas/gschemas.compiled` is generated by `glib-compile-schemas` and should not be committed.

Clean generated files:

```sh
make clean
```

Build extension zip:

```sh
make zip
```

Generated zip name:

```text
cross-switcher@capsudo.github.com.zip
```

### Symlink Local Extension

Create local GNOME Shell extensions directory if it does not already exist:

```sh
mkdir -p ~/.local/share/gnome-shell/extensions
```

Create symlink from GNOME Shell extension UUID path to this checkout:

```sh
ln -sfnT "$PWD" ~/.local/share/gnome-shell/extensions/cross-switcher@capsudo.github.com
```

Verify symlink:

```sh
ls -ld ~/.local/share/gnome-shell/extensions/cross-switcher@capsudo.github.com
```

Expected shape:

```text
... cross-switcher@capsudo.github.com -> /path/to/cross-switcher
```

### Start Nested GNOME Shell

Start isolated GNOME Shell Wayland devkit session:

```sh
dbus-run-session gnome-shell --devkit --wayland
```

If GNOME Shell was already running before creating symlink, restart nested shell so it rescans local extension directories.

Note: GNOME 48 and older:

```sh
dbus-run-session gnome-shell --nested --wayland
```

### Enable Extension

Enable it within the nested shell from either GNOME Extensions app or Terminal:

```sh
gnome-extensions enable cross-switcher@capsudo.github.com
```

Check extension info:

```sh
gnome-extensions info cross-switcher@capsudo.github.com
```

List enabled extensions:

```sh
gnome-extensions list --enabled
```

If command says extension does not exist, usually one of these is true:

- symlink path does not match metadata.json uuid
- schemas/gschemas.compiled was not built
- GNOME Shell started before symlink was created
- command runs in different DBus session than nested shell

## Development Loop

1. Edit JavaScript, CSS or schema files.
2. Run `make all` after schema changes.
3. Restart nested GNOME Shell after JavaScript or schema changes.
4. Reopen preferences after `prefs.js` changes.

### Quick checks before restarting GNOME Shell:

```sh
glib-compile-schemas --strict --dry-run schemas
```
`glib-compile-schemas --strict --dry-run schemas` validates schema XML without writing `schemas/gschemas.compiled`.

On NixOS without tools in current shell:

<details>
<summary>NixOS strict schema check</summary>

```sh
nix shell nixpkgs#glib.dev --command glib-compile-schemas --strict --dry-run schemas
```

</details>

### Quick checks before commit:

```sh
git diff --check
```

`git diff --check` checks for whitespace errors in changed files.
